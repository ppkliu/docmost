# 成員離開檢查清單

適用於「成員被移出某個 space」與「帳號被刪除」兩種情境。兩者的系統行為差很多，
先確認你要做的是哪一種。

| 你要的結果 | 該做的動作 |
|---|---|
| 收回某個 space 的存取，人還在 workspace | 移出 space 成員（可逆，加回去即可） |
| 人徹底離開組織 | 先完成本文「刪除帳號前」的所有前置動作，再刪帳號 |
| 暫時停權（留職停薪、調查中） | 停用帳號（deactivate）—— session 立即失效，space 成員資格保留 |

---

## A. 只是移出 space

系統會自動處理：刪除成員資格、清掉他對該 space 的訂閱與收藏、清掉他的 space
角色快取、寫一筆 `SPACE_MEMBER_REMOVED` 稽核。

移除後畫面會跳出兩則警示（如果適用），**兩則都需要人來決定**：

- [ ] **「Access not fully revoked」** —— 他還透過某個群組進得來。成員清單上他已經
      消失，但門仍然開著。要真的收回，得把他移出該群組，或把該群組移出這個
      space。注意群組是 workspace 範圍的，動它會影響其他 space。
- [ ] **「Public links still active」** —— 他在這個 space 建立過公開連結。連結不會
      因為他離開而失效，任何拿到網址的人仍然讀得到。到
      `設定 > 分享` 逐條檢視，決定保留或撤銷。保留通常是對的（那條連結多半是團隊
      對外在用的），但要有人做這個決定。

其他不會改變的事（正常，不需處理）：

- 他建立的頁面、歷史版本、附件、留言全部留在原地，作者仍然顯示他的名字。
- 他寫的內容仍在知識庫裡，仍會出現在別人的 AI 答案與引用中。

---

## B. 刪除帳號前的前置動作

系統會擋下的（不做完就刪不掉，錯誤訊息會列出是哪些 space）：

- [ ] **他是唯一 space admin 的 space，要先指定接手人。**
      到每個 space 的成員設定加一位 ADMIN，或直接刪掉那個 space。
      為什麼要擋：space 權限只認 `space_members`，一個沒有 admin 的 space，
      連 workspace owner 都無法透過任何 UI 或 API 把自己加回去，只能改資料庫。

系統會自動處理（不需人工）：

- 匿名化（名稱改為 `Deleted user`、email 換成隨機值）、軟刪除
- 刪除所有群組成員資格、space 成員資格、SSO 綁定
- 撤銷所有 session
- **撤銷他建立的所有公開分享連結** —— 帳號都沒了，他掛在外面的匿名入口沒有理由
      繼續存在。撤銷數量會記在 `USER_DELETED` 稽核的 `revokedShareCount`。

需要人工判斷的：

- [ ] **他的內容要不要下架。** 系統刻意不做任何自動處理。
      「作者離職」和「內容失效」是兩件事 —— 大部分情況下他寫的規格、會議紀錄、
      決策紀錄正是最該留下的東西，依作者自動撤下等於系統性地刪掉組織記憶。
      而且知識庫的下架代價不對稱：實體可能已被其他頁面引用，撤一頁不是刪一列。

      做法是交給接手的人逐頁審查，只處理真正過時或不該留的內容，用既有的
      發布／下架機制。要整批處理時那是 space 層級的決定（`publish_required`），
      不是「某個人」層級的決定。
- [ ] **檢查他是否為某些頁面的唯一維護者**，把 owner 交接寫進交接文件。

---

## C. 時間差

移除或降權不是瞬間生效，有兩層快取：

| 層 | 延遲 | 說明 |
|---|---|---|
| Docmost space 角色 | 移除時主動清除，其餘情況最多 5 秒 | `PERMISSION_CACHE_TTL_MS` |
| 知識庫身分解析 | 最多 60 秒 | gateway 每次向 Docmost 現問現答，只快取一個 TTL |

所以「移出後最慢約一分鐘內，知識庫也不再回答該 space 的內容」。
如果是緊急撤權（資安事件），不要只移出 space —— 停用帳號才會立即撤銷 session。
